# MaxX Throttle trusted replay verifier

This private service is the only path from a game client to the authoritative leaderboard archive. It authenticates the player's Steam ticket, confirms Playtest app ownership, runs the shipped game headlessly to deterministically validate the replay, and sends the verified replay plus signed metadata to the Cloudflare leaderboard API.

It does not write Steam Leaderboards. Steam remains the identity provider; D1 and R2 are the leaderboard and replay authority.

## Accepted runs

The verifier accepts completed ranked Time Attack runs with:

- the exact ranked ruleset;
- one human racer and no CPUs;
- an official track from `mxto/steam/leaderboards.json`;
- an official vehicle with matching gameplay evidence;
- canonical input frames and a deterministic finish result.

Practice and unranked runs, loose/custom tracks, curated or ordinary Workshop tracks, and Workshop/custom vehicles are rejected and never sent to the archive.

## Request flow

1. The game sends the replay to `POST /v1/time-attack/submit` with a Steam Web API authentication ticket.
2. The service authenticates the ticket and checks ownership of Playtest app `5001340`.
3. `replay_verifier.py` launches the bundled game headlessly and validates the replay against the checked-in manifest and packaged official content.
4. `authoritative_store.py` HMAC-signs the verified metadata and streams the exact replay bytes to the Cloudflare ingest endpoint.
5. A client success response is returned only after the authority confirms archival.

Every accepted ranked completion is archived, including slower attempts that do not replace a personal or per-vehicle best.

## Required private files

The backend manager expects these files under `%LOCALAPPDATA%\MaxXThrottle\server`:

- `steam_publisher_key.txt` — the Steam publisher Web API key used for authentication and ownership checks;
- `leaderboard-ingest-secret.txt` — the production Worker ingest secret;
- `leaderboard-migration-secret.txt` — the production Worker migration secret used only for the one-time score-only Steam import;
- `cloudflare-tunnel-token.txt` — the tunnel token for the public verifier submission route.

The production ingest secret is generated by `services/leaderboard_api/scripts/provision_secrets.ps1` and retained in that service's ignored `local-secrets` directory. Copying it into the live server directory is an explicit deployment operation.

## One-time Steam history migration

After deploying a fresh verifier bundle, use the backend manager in this order:

1. **Export Steam Snapshot** enumerates every official Steam board and downloads every available attachment into the private server folder. It does not mutate Steam.
2. Review that the snapshot completed. Failed attachment downloads must be resolved before import; a genuinely absent attachment is recorded separately as unavailable.
3. **Import Snapshot to Custom Authority** re-simulates every recovered replay with the deployed verifier, archives valid replay-backed entries, imports only genuinely replay-unavailable scores as visibly non-playable history, and writes an audit report.

Both operations are resumable and idempotent. Invalid attached replays remain invalid audit records and are never silently downgraded into trusted score-only entries.

## Bundle and deployment

Build the release GDExtension first:

```powershell
scons target=template_release -j4
```

The backend manager invokes `build_windows_bundle.ps1`, which exports a dedicated verifier build, copies the official track and vehicle content, includes the Python service modules, and records hashes in `bundle_identity.json`. `install_windows_tasks.ps1` registers the local verifier and Cloudflare Tunnel tasks.

The live launcher is equivalent to:

```powershell
start_windows_bundle.ps1 `
  -PublisherKeyFile C:\secure\steam_publisher_key.txt `
  -LeaderboardIngestSecretFile C:\secure\leaderboard-ingest-secret.txt
```

The production authority defaults to:

`https://mxt-leaderboard-api-production.sndrec32exe.workers.dev`

Use `-LeaderboardApiUrl` to target staging deliberately.

## Environment contract

For direct development runs, configure:

- `MXT_STEAM_APP_ID=5001340`
- `MXT_STEAM_AUTH_APP_IDS=5001340`
- `MXT_STEAM_PUBLISHER_KEY`
- `MXT_LEADERBOARD_API_URL`
- `MXT_LEADERBOARD_INGEST_SECRET`
- `MXT_GAME_EXECUTABLE` or `MXT_GODOT_EXE` plus `MXT_GODOT_PROJECT`
- `MXT_LEADERBOARD_MANIFEST`

Optional tuning includes `MXT_MAX_REPLAY_BYTES`, `MXT_VERIFIER_CONCURRENCY`, `MXT_REPLAY_VERIFY_TIMEOUT_SECONDS`, and `MXT_LEADERBOARD_API_TIMEOUT_SECONDS`.

## Logs

The service writes structured JSONL events to `leaderboard-service.jsonl`. The important terminal events are:

- `submission_rejected` for authentication, eligibility, or deterministic verification failures;
- `submission_failed` with stage `authoritative_archive` for retriable cloud failures;
- `submission_archive_completed` after D1/R2 have accepted the replay;
- `submission_completed` after the client response has been emitted.
